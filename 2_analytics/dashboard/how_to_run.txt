Introduction to run: dashboard

1. Start the API (from project root directory):
    - uv run uvicorn "2_analytics.dashboard.api:app" --reload
    - API will run on: http://127.0.0.1:8000

2. Start the HTML server (from 2_analytics/dashboard/ directory):
    - cd 2_analytics/dashboard
    - python3 -m http.server 5500
    - HTML server will run on: http://127.0.0.1:5500

3. Open browser and enter:
     http://127.0.0.1:5500/

Note:
- Keep both servers running (API on port 8000, HTML on port 5500)
- There are three pages: index.html (Overview), sleep.html and training.html
- The pages fetch /recovery, /sleep and /workouts from http://127.0.0.1:8000; /weather remains available but no page requests it
- The chat panel posts questions to http://127.0.0.1:8000/chat
- Chat needs a local Ollama server (default http://localhost:11434) and a tool-capable model. The default is llama3.2:latest via OLLAMA_MODEL=ollama_chat/llama3.2:latest
- Make sure the database is at: 0_data/database/warehouse.duckdb
- Make sure these tables exist: marts.fct_whoop_recovery, marts.fct_whoop_sleeps, marts.fct_whoop_sleep_quality, marts.fct_whoop_workouts, marts.fct_weather_daily
- DuckDB only allows one writer at a time — if Airflow is mid-run against warehouse.duckdb, the API's read-only connections may briefly fail; just retry.
